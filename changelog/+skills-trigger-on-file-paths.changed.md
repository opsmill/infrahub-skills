The managing-generators, managing-transforms, managing-checks, managing-objects and managing-menus skills now name the files they cover in their descriptions, so Claude Code can load them when your request names a file but not the task: generators for `.py` and `.gql` files under `generators/`, transforms for `.py` files under `transforms/` and `.j2` files under `templates/`, checks for `.py` files under `checks/`, objects for YAML files with `apiVersion: infrahub.app/v1` and `kind: Object`, and menus for YAML files under `menus/` or with `kind: Menu`. A `.gql` file under `queries/` triggers the transforms or checks skill, depending on which one uses the query in `.infrahub.yml`. No eval tests this triggering yet. The removed `SessionStart` hook used to give Claude these path rules. The installation page now has a `CLAUDE.md` section you can add to your Infrahub repository to make Claude read the matching skill before it edits one of these files.
